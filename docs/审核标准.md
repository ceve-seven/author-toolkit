# AI 小说创作系统 — 全流程审核标准

> 用途：在新会话中运行完整 20 步流程后，逐项核验系统是否达到预期要求。
>
> 判定规则：**全部「必须通过」项均通过**，则该步骤判定为 **✅ 通过**。任何一项「必须通过」失败，则该步骤判定为 **❌ 不通过**。

---

## 一、前置条件检查

在开始第零步之前，确认以下条件：

| # | 检查项 | 判定 | 说明 |
|---|--------|------|------|
| P1 | 项目根目录为 `Agent-Native-novel/` | 必须通过 | 工作目录必须正确 |
| P2 | `src/` 目录包含所有模块、引擎、同步代码 | 必须通过 | 确认系统完整性 |
| P3 | 数据库文件 `data/novel.db` 不存在或为空 | 推荐 | 全新测试应使用空数据库 |
| P4 | `output/` 目录为空 | 推荐 | 避免旧数据干扰 |
| P5 | `chroma_client` 可初始化 | 必须通过 | 向量库可正常创建 |
| P6 | AI Agent **未创建任何 `.py` 脚本文件** | 必须通过 | 全部代码在会话中直接执行 |

## 四、全局规则合规检查

以下规则适用于**全部 19 步**，需要在每一步执行后检查：

| # | 检查项 | 判定 | 验证方法 |
|---|--------|------|----------|
| G1 | 未创建任何 `.py` 脚本文件 | 必须通过 | 检查工作目录无 `_run_step*.py` 等文件 |
| G2 | 一次只执行一个步骤 | 必须通过 | 每步之间有结果展示 + 用户确认 |
| G3 | 每步通过 `StepExecutor.execute()` 执行 | 必须通过 | 不得直接调用 `module.run()` |
| G4 | 每步使用 `with session.begin()` 事务 | 必须通过 | 数据库操作在事务中 |
| G5 | 每步后检查 `result.sync_status` | 必须通过 | `sync_status` 非空 |
| G6 | 每步后展示 `output/` 目录内容 | 必须通过 | Agent 用 `os.walk()` 检查并展示 |
| G7 | 与用户自然语言交流 | 必须通过 | Agent 提问、展示结果、等确认 |
| G8 | 约束违规展示给用户 | 必须通过 | `result.constraint_violations` 不为空时展示 |
| G9 | 步骤 13-14, 17-19 强制质量审查不可跳过 | 必须通过 | `needs_review=True` 的步骤必须有审查结果 |
| G10 | 分卷不以整数为边界 | 必须通过 | 约束引擎拦截 `length % 10 == 0` 且无重力来源 |
| G11 | 用户反馈优先处理 | 必须通过 | 用户提修改意见时先更新数据再下一步 |
| G12 | SQL 查询全部使用 `text()` 包装 | 必须通过 | 无 raw SQL warning |
