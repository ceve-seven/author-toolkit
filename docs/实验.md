## 核心设计要点

**统一接口**：所有模块继承 `BaseModule`，实现 `run(context, content) -> ModuleResult` 和 `validate(result) -> list[str]` 两个方法。

**存储逻辑**：统一通过 `context["db_session"]` 使用 SQLAlchemy `text()` 执行参数化 SQL 写入对应表。ID 生成通过 `src.utils.id_generator.generate_id()`。

**依赖管理**：`ModuleRegistry` 单例通过 `depends_on` 列表自动拓扑排序，支持 `get_sorted_modules()` 获取有序执行队列。

## 为什么 AI Agent 会自己创建脚本

根本原因在于 `agent_entry.py` 的设计方式。它包含两个对 AI Agent 不友好的特性：

### 1. `_agent_generate()` 是个空桩方法

[engine.py:L305-L315](file:///d:/01-项目/AI小说创作系统/Agent-Native-novel/src/workflow/engine.py#L305-L315)

```python
def _agent_generate(self, step_name: str, context: Dict[str, Any]) -> Any:
    """Agent 内容生成——此处为桩方法，Agent（LLM）在运行时自动填充"""
    content = {
        "step_name": step_name,
        "context": context,
        "generated_by": "agent",
        ...
    }
    return content  # ← 没有实际内容生成！
```

这个方法名写的是"Agent内容生成"，但实际什么都没生成。它期望在运行时由 LLM 填充，但没有任何 LLM 调用逻辑。

### 2. 工作流依赖 `input()` 交互

[engine.py:L242-L265](file:///d:/01-项目/AI小说创作系统/Agent-Native-novel/src/workflow/engine.py#L242-L265)

每个环节都需要用户输入 `执行/修改/跳过/停止` 等命令——这对 AI Agent 来说是无法自动处理的。

所以当 AI Agent 看到这个系统时，它发现：
- 没有真正的 LLM 集成
- 全都是 `input()` 交互等待
- `_agent_generate` 是个空壳

**于是它选择自己写一个——因为它觉得这系统没法直接用。**
