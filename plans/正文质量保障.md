章节正文是整个体系的最终输出端。前面所有模块——世界观、人物、势力、物品、伏笔、细纲——都是为这一环节积蓄的势能。如果正文垮了，前面全白做。

你提的五个问题里，字数控制是最实际的痛点。AI 写小说字数控不住，根本原因是「给一个话题让它自由展开」，它没有内部的结构化分配机制。这个问题有解，但需要把生成流程拆开——不靠 AI 自觉，靠系统约束。

下面从约束注入、分层生成、字数控制、AI 审查、读者吸引力五个方面展开。

---

## 一、约束注入：正文生成前，系统替 AI 记住一切

正文生成的起点不是「开始写第 N 章」，而是「拉取第 N 章的全部约束」。这个流程和细纲生成时的约束拉取一致，但正文需要更细粒度——约束要下沉到**句子级可操作指令**，而不是「本章需要注意 CHAR-001 左臂受伤」这种描述性提示。

### 1.1 正文生成约束文件

当用户发出「生成第 N 章正文」指令时，AI 自动从中央档案库拉取并生成一份《第 N 章约束文件》。这份文件在正文生成全程中作为不可违背的边界条件：

```
=== 第 28 章正文约束文件 ===

【细纲绑定】（来源：第 28 章已审核通过的细纲）
  场景数量：3
  场景一：仓库发现 / POV CHAR-001 / 核心事件：发现 CHAR-002 的痕迹
  场景二：CHAR-003 住所 / POV CHAR-003 / 核心事件：处理 ITEM-007
  场景三：赴约 / POV CHAR-001 / 核心事件：CHAR-006 的警告

【人物状态·句子级约束】以下每条必须在正文中通过具体描写兑现，不能仅靠叙述说明

  CHAR-001：
    左臂伤势 → 必须在至少一个动作场景中产生具体影响
      （错误写法：「他的左臂还在疼。」这是叙述说明。）
      （正确写法：「他用右手去够高处的箱子，左臂下意识地贴在身侧，
       像一只受伤的翅膀。指尖碰到箱沿的瞬间，左边的肩膀发出了警告。」）
    
    知识边界 → CHAR-001 不知道 FAC-004 的参与，正文中他对任何涉及 FAC-004 的信息
      必须表现为「不理解」「忽略」或「误判」
    
    语气指纹 → 参考 CHAR-001 语气指纹档案：
      词汇池偏好：短句、具象名词、回避抽象形容词
      句式偏好：主谓结构为主，偶尔用碎片句（不超过全文 8%）
      禁忌表达：不用「突然意识到」「不知为何」「莫名其妙地」等伪心理描写
    
    当前情感状态 → 「信任正在瓦解」不能直接写「他不再信任 CHAR-002」
      必须通过三个层面的具体呈现：
      ① 身体反应（看到 CHAR-002 留下的痕迹时，身体先于意识做出什么反应？）
      ② 认知偏差（他开始用什么新的方式解读 CHAR-002 的过往行为？）
      ③ 行为改变（他做了什么之前不会做的事，或没做什么之前会做的事？）

  CHAR-003：
    POV 约束 → 本卷首次以 CHAR-003 为 POV，需要在该场景开头用 2-3 句建立其
      感知世界的独特方式（参考 CHAR-003 人物档案中的感知过滤器）
    知识边界 → 不知道 CHAR-001 对 CHAR-002 的怀疑。正文中 CHAR-003 对 CHAR-001
      的行为解读必须基于「完全信任」这一前提，形成读者层面的戏剧反讽

  CHAR-006：
    弧线阶段约束 → 处于「表面优势」阶段，正文中必须做到：
      ① 他的自信不是虚张声势——在本章这个时间点，他真的占优
      ② 但他的话语中埋下一条未来回看才成立的暗示（对应 FORE-031 的埋设）

【关系约束】
  CHAR-001 ↔ CHAR-002（本章不直接同框，但关系通过 CHAR-001 的发现间接推进）：
    CHAR-001 对 CHAR-002 痕迹的反应，必须比上一章（第 27 章）更进一步
    对比第 27 章的情感状态：当时是「发现隐瞒后的震惊」
    第 28 章应该推进至：从震惊转向「冷静的重新评估」——这比震惊更可怕
    禁止写 CHAR-001 内心独白「原来他一直在骗我」——这是第 27 章已经完成的情绪

  CHAR-001 ↔ CHAR-003（场景二和场景三之间，通过未接的电话间接呈现）：
    CHAR-003 打给 CHAR-001，CHAR-001 没接。
    CHAR-003 的理解方式（基于信任前提）：担心而非怀疑
    CHAR-001 不接的原因（基于怀疑加深）：不想在情绪波动时和 CHAR-003 对话，
      因为他知道 CHAR-003 能听出来——他的目标是隐瞒，不是疏远

【物品约束】
  ITEM-005（CHAR-001 持有，部分损坏）：
    必须在场景一中被使用或至少被提及能力受限
    可以写 CHAR-001 习惯性地想去用它，然后想起它坏了——
    这个微小的挫败感可以承载「他正在失去他依赖的东西」的主题回响

  ITEM-012（CHAR-001 持有，完好，计划第 35 章回收）：
    本章最多出现 1 次，且必须是「不经意地被注意到」而非「被强调」
    禁止写法：「他摸了摸口袋里的 ITEM-012，确认它还在。」
    允许写法：「他弯腰捡东西时，口袋里的重量偏了一下。他没在意。」

  ITEM-007（CHAR-003 持有）：
    需要在场景二中出现，但仅用于建立存在感
    禁止在本章揭示或暗示其核心能力

【伏笔约束】
  需回收：FORE-003（仓库那扇锁着的门）
    回收方式约束：不能写成「他打开了那扇第 8 章出现过的门」——
    需要让读过第 8 章的读者自己认出来，没读过的也能正常理解场景
    实现方式：通过门的细节描写（材质、位置、第 8 章出现过的某个特征）触发读者记忆，
    而非通过叙述者直接提醒

  需埋设：FORE-031（CHAR-006 提到的名字）
    埋设方式约束：名字必须自然地出现在对话中，不能是 CHAR-006 刻意宣布的
    CHAR-001 必须表现出「没追问」——但他的「没追问」必须有具体原因
    （不是「他没在意」，而是「那一刻有什么别的事占据了他的注意力」）

  需轻触：FORE-007, FORE-015
    轻触方式：一个细节、一个反应、一个短暂的回声——读者几乎注意不到的程度

【主题约束】
  本章主题推进：信任与怀疑
  推进方式：不是通过 CHAR-001 的思考（这会让主题变成说教），而是通过一个
    具体的、不可逆的小选择——CHAR-001 选择不告诉 CHAR-003 他发现了什么。
    这个选择的代价不是立即显现的，但它改变了 CHAR-001 和 CHAR-003 关系的
    底层地基。本章结束时 CHAR-003 还不知道，但读者知道。
    主题在这一刻从「CHAR-001 怀疑 CHAR-002」推进为「CHAR-001 开始对所有人
    保持距离」——信任问题的范围扩大了。

【节奏约束】
  本章在卷内位置：第二卷中段，上升斜坡
  开篇力度：中（不是卷首，不需要爆炸性开场）
  情感曲线：不安 → 寒意 → 犹豫 → 平静（CHAR-003段落）→ 警惕 → 冲击 → 悬空（结尾钩子）
  禁止：本章结尾不能有「平静的回落」——必须悬空，把读者推入第 29 章
  段落节奏：场景一和场景三的段落应偏短（1-4句），场景二可以稍长（2-6句）——
  CHAR-003 的 POV 段落节奏本身就是他性格的一部分

【字数约束】
  总字数：3500-4200 字
  场景一分配：1200-1400 字
  场景二分配：1000-1200 字
  场景三分配：1300-1600 字
  （详见下面第三节：字数控制体系）
```

这份约束文件是所有质量保证的基础。正文生成时，AI 的每句话都在这些约束的边界内运行。

### 1.2 约束文件的生成是自动的

用户不需要手动编写上述任何内容。用户只说「生成第 28 章正文」，AI 自动从中央档案库拉取所有相关数据，编译成约束文件。用户可以选择「显示约束文件」来审核（如果对某一个约束有异议，比如「CHAR-003 的场景我不想用他的 POV，换成 CHAR-001 的视角来写」），也可以直接说「开始写」——AI 默认按约束执行。

## 二、分层生成：不一次性生成全章，按场景独立生成后拼合

### 2.1 为什么不一次性生成全章

AI 一次性生成整章正文时（比如「写第 28 章，4000 字」），会发生以下问题：

- **字数漂移**：AI 写到某个场景时刹不住，后面场景被挤压或草草结束
- **质量不均**：第一个场景很细腻，最后一个场景像赶工
- **约束遗漏**：4000 字跑完，AI 可能会忘记在场景三里体现 CHAR-001 的左臂伤
- **修改困难**：用户说「场景二不行，重写」时，整个 4000 字要重新生成，场景一和三也被连带

### 2.2 逐场景生成流程

```
用户：「生成第 28 章正文」

AI：
  第一步：拉取约束 → 编译约束文件
  第二步：输出场景一「仓库发现」的约束摘要（上文约束文件中场景一相关部分）
          用户确认或调整后 → 生成场景一正文
  第三步：场景一生成完毕 → 显示字数 → 用户审核
          如需修改 → 在场景一范围内修改（不波及其他场景）
  第四步：场景一通过 → 输出场景二「CHAR-003 住所」的约束摘要
          生成场景二正文 → 字数统计 → 审核 → 通过
  第五步：场景三同理
  第六步：三个场景全部通过 → AI 做一次全章拼合
          - 检查场景之间的过渡是否平滑
          - 检查情感曲线是否与细纲中的规划一致
          - 检查全章总字数
          - 输出「第 28 章完整正文」
```

### 2.3 场景间过渡的拼合微调

逐场景生成后，场景之间的过渡段落需要单独处理——因为场景一和场景二是分别生成的，AI 不知道上一个场景的结尾细节，拼合时需要微调：

```
拼合微调清单：

场景一 → 场景二的过渡：
  场景一结尾：CHAR-001 离开仓库，收到 CHAR-006 的信息
  场景二开头：CHAR-003 在住所
  过渡方式：时间跳跃是合法的（同一夜，稍晚），但需要一个过渡锚点——
  可以通过 CHAR-003 看到的某个景象（比如窗外的天色变化）来暗示时间流逝，
  同时和场景一的「凌晨」形成时间线上的呼应。

场景二 → 场景三的过渡：
  场景二结尾：CHAR-003 联系 CHAR-001，未获回应
  场景三开头：CHAR-001 前往赴约地点
  过渡方式：视角切换 + 时间推进。CHAR-003 的未接来电在 CHAR-001 的手机
  屏幕上显示——这个细节连接了两个场景，同时承载了关系约束中「CHAR-001 
  选择不回应」的主题推进。
```

拼合微调的字数极少（通常 50-150 字），不会影响各场景已审核通过的内容。

## 三、字数控制体系：第一次输出就在规定范围内

这是你强调的核心问题。AI 写小说字数失控，不是 AI 的问题，是生成方式的问题。一次性说「写 4000 字」→ AI 凭感觉写 → 结果在 2500 到 6000 之间随机漂移。

解决方案不是「更精准的提示词」，而是**场景级字数预算 + 实时统计 + 逐段微调**。

### 3.1 全章字数预算的结构化分配

全章目标字数不是平均分给各个场景，而是根据场景在章内的叙事权重分配：

```
=== 第 28 章字数预算（目标：3800 字，允许范围：3500-4200）===

场景一（仓库发现）：权重 35% → 1330 字（允许范围 1200-1400）
  理由：本章的核心事件载体，需要足够空间展开发现过程、回收 FORE-003、
       体现 CHAR-001 的身体状态和情感变化

场景二（CHAR-003 住所）：权重 25% → 950 字（允许范围 850-1050）
  理由：功能场景，建立 CHAR-003 的 POV、轻触 ITEM-007、铺设戏剧反讽。
       不需要太多篇幅，但需要足够的沉浸感。如果过短，CHAR-003 的 POV 会
       像走过场；如果过长，会拖慢本章的整体节奏

场景三（赴约）：权重 35% → 1330 字（允许范围 1200-1400）
  理由：本章的情感高潮和主题推进承载场景。CHAR-006 的警告对话是本章的
       叙事重头戏，需要足够的空间让对话有呼吸感

过渡段落：权重 5% → 190 字（允许范围 100-250）

总计目标：3800 字（在 3500-4200 范围内）
```

### 3.2 场景内字数的动态控制

为每个场景设定字数预算后，AI 在生成场景正文时采用**分段输出 + 实时字数统计**的方式，而非一次性输出全部场景内容。

场景的生成拆分为段落组：

```
场景一生成计划（目标 1330 字）：

段落组 1（开场·进入仓库）：约 300 字
  → 环境描写 + CHAR-001 的身体状态（左臂伤） + 情绪锚点

段落组 2（发现过程·第一部分）：约 350 字
  → 搜查仓库的过程，发现表面痕迹

段落组 3（发现过程·第二部分·FORE-003 回收）：约 400 字
  → 发现那扇门开了，进入内部，回收 FORE-003

段落组 4（高潮发现 + 情感转折）：约 280 字
  → 发现关键痕迹，CHAR-001 的认知开始转变
  → 做出选择：不告诉 CHAR-003

总计预估：1330 字
```

AI 在生成每个段落组后显示实际字数。如果某一段落组超出预算 15% 以上，AI 在生成下一段落组时自动压缩：

```
场景一 - 段落组 2 生成完毕：420 字（预算 350 字，超出 20%）

⚠️ 字数预警：本场景当前累计 720 字 / 目标 1330 字（剩余 610 字）
  段落组 2 超出预算的主要原因是环境描写的细节密度过高。
  建议：段落组 3 和 4 合并生成，预算调整为 610 字，自动提升叙述效率。

继续生成？（Y / 缩减段落组 2 后继续）
```

### 3.3 超出预算时的处理策略

当某个场景超出字数预算时，不进行粗暴的删减（删减会破坏已经建立起来的叙事密度和节奏），而是区分两种情况处理：

**情况一：轻度超出（超出 ≤15%）**

不做删减。在后续段落组中自动提升叙述效率来平衡——比如合并两段过渡性描写、减少一句环境细节、把一段内心活动从展开式改为浓缩式。最终场景总字数在允许范围内即可。

> 「场景一全部完成：1420 字（预算 1330，超出 6.7%，在允许范围内✅）」

**情况二：中度超出（超出 15%-30%）**

AI 输出超出的原因分析 + 两个方案供用户选择：

```
场景一全部完成：1650 字（超出 24%）

⚠️ 超出原因：段落组 3 的 FORE-003 回收场景展开过于详细，包含了对第 8 章
   原始场景的过多闪回。

方案 A（场景内精简）：将 FORE-003 的闪回从完整段落改为两个细节碎片，
   保持回收效果的同时减少约 200 字。修改后预估 1450 字。

方案 B（全局吸纳）：保留当前版本（1650 字），从场景三的预算中扣除 200 字，
   约束场景三生成时自动压缩。修改后：场景一 1650 + 场景二 950 + 
   场景三 1130 + 过渡 150 = 全章 3880 字。

推荐方案 A（场景一是本章核心，应保留完整力量；场景三的对话场景不应被压缩）。
请确认。
```

**情况三：重度超出（超出 > 30%）**

AI 停止生成，要求用户确认是否调整预算分配。重度超出通常意味着细纲中该场景的设计过于复杂，可能需要拆分到两个章节或者简化事件。

### 3.4 字数不足时的补充策略

字数不足比字数超出更危险——写少了意味着场景可能缺乏必要的沉浸感。补充时不能注水（加废话），而是做「深度扩展」：

```
场景二完成：780 字（预算 950，不足 170 字）

分析：场景二偏短的主要原因是 CHAR-003 的感知过滤器建立不足——
    他的 POV 还没有足够「像他」。

建议补充（任选其一或组合）：

  A. 扩展 CHAR-003 与 ITEM-007 的互动（+80 字）：
     不是增加物品描述，而是展示他处理这件物品时的特定方式——
     这同时服务物品存在感的建立和人物性格的呈现。

  B. 增加一个 3-4 句的环境细节段落，通过 CHAR-003 的独特视角过滤（+90 字）：
     他注意到的不是房间里有什么，而是「缺了什么」——
     这定义了他观察世界的方式，也为后续情节做性格铺垫。

请选择或提供方向。
```

### 3.5 全章拼合后的最终字数微调

三个场景全部通过后，全章拼合时做最终字数检查：

```
=== 第 28 章最终字数 ===

场景一：1380 字 ✅
场景二：960 字 ✅
场景三：1410 字 ✅
过渡段落：180 字 ✅
────────────────
全章总计：3930 字（目标 3800，偏差 +3.4%，✅在允许范围内）

字数校验通过。
```

如果全章总字数超出允许范围（比如 4300 字），AI 不会对整章做均等删减——均等删减破坏所有场景的节奏。而是识别哪个场景的字数密度最低（即内容最可以压缩），对该场景做定向精简。

## 四、AI 审查体系：不是审一次，是分层交叉审核

正文写完后，AI 的审查不是「读一遍看看有没有问题」——这是最容易被 AI 痕迹溜过去的方式。审查分为四层，每一层有独立的检查标准和通过条件。

### 4.1 第一层：设定一致性审查（硬约束审查）

这一层只做一件事：逐条检查正文中提到的每一个设定元素，和中央档案库中的当前数据是否一致。

审查方式：不是靠 AI 「读一遍感觉对不对」，而是**关键词提取 + 数据库交叉比对**：

```
=== 第 28 章设定一致性审查 ===

提取正文中涉及的所有设定元素：
  - 人物：CHAR-001, CHAR-002（间接提到）, CHAR-003, CHAR-006
  - 物品：ITEM-005, ITEM-007, ITEM-012
  - 势力：FAC-003（仓库场景地点）, FAC-005（CHAR-006 提及）
  - 地点：FAC-003 废弃仓库, CHAR-003 住所
  - 伏笔：FORE-003（回收）, FORE-007（轻触）, FORE-015（轻触）, FORE-031（埋设）

逐条比对：

CHAR-001：
  ✅ 左臂伤势在多处体现（够到箱子、推门、接住掉落物）
  ✅ 知识边界遵守：对 FAC-004 相关信息表现出「忽略」（CHAR-006 暗示时未追问）
  ✅ 语气指纹：短句占比 72%，在主谓结构的偏好范围内
  ✅ 情感状态通过三个层面呈现：身体反应（发现痕迹时手指发冷）、
     认知偏差（重新解读 CHAR-002 的一句话）、行为改变（选择不告诉 CHAR-003）
  ✅ 未使用禁忌表达（无「突然意识到」「不知为何」等）

CHAR-003：
  ✅ POV 建立：开头 3 句通过「他注意到的是缺了什么」定义了感知过滤器
  ✅ 知识边界遵守：对 CHAR-001 的异常行为解读为担心而非怀疑

CHAR-006：
  ✅ 弧线阶段正确：自信中带有真实的掌控感，非虚张声势
  ✅ FORE-031 埋设：名字在对话中自然出现，CHAR-001 因 CHAR-003 的来电分散注意力而未追问

ITEM-005：
  ✅ 在场景一中提及能力受限（CHAR-001 习惯性想用，然后想起损坏）

ITEM-012：
  ✅ 仅在场景一中出现 1 次（弯腰捡东西时口袋重量偏移），未过度强调

ITEM-007：
  ✅ 在场景二中出现，CHAR-003 处理方式展示性格而非揭示能力

FORE-003：
  ✅ 已回收，通过门的细节（材质、锁的样式）触发读者记忆，未直接提醒

FORE-031：
  ✅ 已埋设，符合载荷设计

FORE-007, FORE-015：
  ✅ 已轻触（场景一某个反应回扣 FORE-007，场景二某个细节暗示 FORE-015）

────────────────
一致性审查结果：全部通过 ✅（0 处不一致）
```

如果发现不一致，AI 不直接修改——而是标注问题类型和建议方案，让用户选择：

```
⚠️ 发现 1 处不一致：

CHAR-001 在场景三中说了「我不确定能不能相信任何人」。
  问题：CHAR-001 的语气指纹档案中「禁忌表达」包含「不确定」这类模糊心理词。
       他的语气指纹定义是「用具体行动表达不确定性，而非标签化心理状态词汇」。
  建议修改：删除这句话，用 CHAR-001 的一个具体行动替代——
   比如他拿起又放下一件东西的动作，承载同样的「不确定」含义。

请确认是否修改 / 保留原句（覆盖语气指纹约束）。
```

### 4.2 第二层：逻辑链审查

这一层检查正文的内部逻辑——不是因为设定错误，而是因为叙述自身产生了矛盾。

审查方式：AI 提取正文中所有「因果事件对」，逐对推演是否成立：

```
=== 第 28 章逻辑链审查 ===

事件链提取：

1. CHAR-001 进入仓库 → 发现 CHAR-002 的痕迹 → 重新评估 CHAR-002
   ✅ 逻辑链完整：动机（查证怀疑）→ 行动（搜查）→ 结果（发现痕迹）→ 反应（重新评估）

2. CHAR-001 发现仓库的门开了（FORE-003 回收）→ 进入内部
   ✅ 成立：第 8 章这扇门是锁着的，现在开了。CHAR-001 在第 8 章时曾试图打开这扇门。
   逻辑自洽。

3. CHAR-003 联系 CHAR-001 → CHAR-001 未接
   ✅ 成立：CHAR-001 的情感状态（场景一结尾的「寒意」）足够解释他不接的行为。
   但需确认：CHAR-001 平时会接 CHAR-003 的电话吗？
   查阅 REL-001 档案：CHAR-001 和 CHAR-003 的过往通话记录（第 10/15/20 章）——
   CHAR-001 每次都接了。因此这次不接是一个「行为改变」，
   符合本章主题「信任问题范围扩大」的推进方向。

4. CHAR-006 的警告 → CHAR-001 重新审视之前的判断
   ✅ 成立：警告内容的具体性和 CHAR-001 刚刚发现的痕迹形成共振，
   两件事互相印证，CHAR-001 的认知转变有充分的叙事推力。

────────────────
逻辑链审查结果：全部通过 ✅（0 处逻辑断裂）

补充说明：
  事件 3 中 CHAR-001 不接电话的行为，建议在第 29 章由 CHAR-003 直接或间接提及——
  让「这次没接」成为一个被注意到的变化，而非一笔带过的细节。
```

### 4.3 第三层：文学质感审查 + AI 痕迹检测

这一层检查正文的文学质量和 AI 痕迹。之前讨论过的六大 AI 痕迹特征在这里进入实际操作阶段：

```
=== 第 28 章文学质感审查 ===

【句式匀质化检测】
  扫描全文句式长度分布：
    1-10字句：18% ✅（未低于 15% 警戒线）
    11-20字句：45% ✅
    21-30字句：25% ✅
    30字以上句：12% ✅
  句式多样性指数：0.78（0.5-0.85 为健康区间）✅

【过渡词依赖检测】
  扫描过渡词使用频率：
    「然后」：2 次 ✅
    「接着」：1 次 ✅
    「随后」：0 次 ✅
    「与此同时」：0 次 ✅
  未发现过度依赖。

【情感说明化检测】
  扫描情感直接说明：
    「他感到恐惧」类句式：0 次
    「他意识到」类句式：0 次（禁忌表达已在上层审查中拦截）
  情感呈现方式：100% 通过身体/行动/对话/环境承载 ✅

【对话功能化检测】
  扫描对话中纯粹推进信息的句子：
    疑似功能句：「你应该知道 FAC-005 在计划什么。」
    分析：这句话同时承载了信息传递和 CHAR-006 的权力姿态（他在「告知」而非「协商」），
    不算纯功能对话。但建议增加一个非功能性的小细节——比如 CHAR-006 说这句话时
    做的一个不相关的小动作——来进一步打破纯信息交换感。
    严重程度：低（可选择性修改）

【描写模板化检测】
  扫描高频描写模式：
    环境描写中「光」的出现频率：5 次（在 3930 字中略偏高）
    「光」的描写方式：3 次使用了「昏暗的」「微弱的」「冷色的」等常见搭配
    建议：将其中 1 处「光」的描写替换为声音或温度感知，打破视觉依赖。

【安全化倾向检测】
  扫描回避的叙事选择：
    场景三中 CHAR-006 的警告内容：具体且有代价暗示 ✅
    CHAR-001 在场景一结尾的选择（不告诉 CHAR-003）：有道德灰度 ✅
    CHAR-003 对 CHAR-001 的信任：未被处理为「天真」，而是「信息不对称下的合理判断」✅

────────────────
文学质感审查结果：通过（2 处建议性修改，非必须）✅
```

### 4.4 第四层：读者吸引力审查

这一层不看「写得对不对」，只看「读不读得下去」：

```
=== 第 28 章读者吸引力审查 ===

【开篇吸引力】
  第一段：CHAR-001 进入仓库的环境描写 + 身体状态
  第一段是否包含「异常」？✅（凌晨的仓库 + 左臂伤势，建立了情境异常）
  第一段是否提出隐性疑问？✅（他在找什么？门为什么开了？）
  第一段字数：87 字（建议开篇不超过 120 字，✅）

【信息释放节奏】
  本章需释放的新信息：
    - FORE-003 回收（仓库门后的空间）→ 场景一中部释放
    - CHAR-002 的痕迹 → 场景一后部释放
    - CHAR-006 的警告 → 场景三中部释放
    - FORE-031 埋设（名字）→ 场景三后部释放
  信息释放间隔（按字数）：
    释放 1 → 420 字 → 释放 2 → 380 字 → 释放 3 → 520 字 → 释放 4
  ✅ 间隔分布均匀，无信息倾泻或信息饥饿区

【场景结尾钩子强度】
  场景一结尾：「他关掉手电，让仓库重新陷入黑暗。手机屏幕亮了一下——
    CHAR-003 的名字。他等屏幕暗下去，才推开门出去。」
    钩子类型：行为钩子（他选择不接）
    强度：中高 ⬆（读者会想知道 CHAR-003 此刻在想什么）

  场景二结尾：「CHAR-003 放下手机。窗外的天色还是沉的，但最黑的那一段
    已经过去了。他不知道的是，有些事情正好相反。」
    钩子类型：信息不对称钩子（读者知道 CHAR-003 不知道的）
    强度：中 ⬆

  场景三结尾：「CHAR-006 的脚步声远了。CHAR-001 站在原地看着他的背影变小，
    直到消失在转角。然后他才发现自己在发抖——不是因为冷。」
    钩子类型：身体反应钩子（暗示情感的冲击大于他愿意承认的）
    强度：高 ⬆（强制读者追问：他接下来会做什么？）

【全章结尾钩子强度】
  全章最后一句话：CHAR-001 发现自己发抖
  钩子有效性：高（不是信息钩子，是情感钩子。不告诉你接下来发生什么，
    但让你必须翻到下一页去确认角色的状态）

【情感投入度估算】
  基于场景数量、POV 切换频率、对话与叙述比例：
  本章读者情感投入度预估：8.2/10
  理由：单一主线（CHAR-001 的发现和选择），POV 仅切换 1 次（CHAR-003 段落
    作为呼吸和对比），对话场景（场景三）有足够的张力。唯一可能拉低投入度的是
    CHAR-003 场景——如果读者对 CHAR-003 尚未建立足够的情感连接，这个场景
    可能会被略读。

────────────────
读者吸引力审查结果：通过（1 处建议：监测读者对 CHAR-003 场景的反馈）✅
```

### 4.5 审查的触发时机和用户交互

审查不需要单独触发。当用户说「场景一写好了，继续场景二」时，AI 自动完成场景一的审查并输出结果（简略版）。当全章完成后，AI 自动运行全部四层审查。

用户可以随时要求单独运行某一层审查：

> 「检查一下逻辑链。」→ AI 只运行逻辑链审查

> 「AI 痕迹检测。」→ AI 只运行文学质感审查中的 AI 痕迹检测部分

审查结果中的问题分三级：

| 级别 | 含义 | 处理方式 |
|------|------|---------|
| 🔴 必须修改 | 设定不一致、逻辑断裂、字数严重超标 | 禁止通过，必须修改后才能进入下一章 |
| 🟡 建议修改 | AI 痕迹较明显、句式开始匀质化、钩子偏弱 | 推荐修改，用户可选择保留 |
| 🟢 参考 | 风格建议、可选的优化点 | 用户自行判断 |

## 五、生成指令集

**正文生成指令**：

> 「生成第 N 章正文，目标字数 XXXX。」→ AI 拉约束 → 逐场景生成 → 拼合 → 审查

> 「显示第 N 章约束文件。」→ 查看约束但暂不生成

> 「从场景二开始重写，场景一保留。」→ 仅重新生成指定场景

> 「场景三的字数预算从 1300 调整到 1800，从场景二扣除 500。」→ 手动调整预算分配

**审查指令**：

> 「全面审查第 N 章。」→ 四层审查全部运行

> 「设定一致性审查。」→ 仅运行第一层

> 「逻辑链审查。」→ 仅运行第二层

> 「AI 痕迹检测。」→ 仅运行第三层的 AI 痕迹检测部分

> 「读者吸引力审查。」→ 仅运行第四层

**修改指令**：

> 「场景一中 CHAR-001 的发现过程太顺利了，加一个障碍。」→ AI 在约束范围内修改指定场景

> 「全章结尾太温和了，钩子不够强。」→ AI 重写最后 200 字

> 「把本章从 3800 字压缩到 3200 字。」→ AI 分析密度，定向压缩而非均等删减

## 总结：正文质量的五层保障

| 层级 | 保障内容 | 保障方式 | 时机 |
|------|---------|---------|------|
| 约束注入 | 所有设定元素被转化为句子级可操作指令 | 中央档案库自动拉取 + 编译约束文件 | 生成前 |
| 分层生成 | 逐场景独立生成，每个场景在自己的约束内运行 | 场景拆分 + 段落组输出 + 实时字数统计 | 生成中 |
| 字数控制 | 第一次输出就在目标范围内 | 场景级预算 + 段落组实时跟踪 + 超出/不足的分级处理 | 生成中 |
| 四层审查 | 设定一致性、逻辑链、文学质感、读者吸引力 | 关键词比对 + 事件链推演 + 句式分布扫描 + 钩子强度评估 | 生成后 |
| 用户审核 | 用户的创作判断 | 逐场景通过 + 审查结果分级处理（必须/建议/参考）| 全流程 |
